Excel 加载项（`.xlam`，走「Excel 加载项」通道，**不注册 COM**），用于在审计底稿中批量插入附件超链接：

> 多选文件 → 自动归档复制到底稿同级「附件」文件夹 → 以**相对路径**插入超链接

与鼎信诺 COM 加载项**可共存**；宏全部在加载项内，**底稿文件保持无宏**，不影响鼎信诺读取与归档剥离。

> [!IMPORTANT]
> **正式分发渠道：[GitHub Releases](https://github.com/jasonisbrave/attachlink/releases)**（下载 `AttachLink-<版本>.zip`，发布说明内附 SHA-256 校验值；企业网盘仅作归档同步载体，不作安装包分发）。

## 环境要求

- Windows + 桌面版 Excel 2010 及以上；PowerShell 5.1+
- **WPS 表格亦支持（v1.3.1 起菜单为 4 顶项浓缩版）**
  - 仅在 WPS **「表格」**组件中实现，**「智能表格」中无法使用**（2026-11-21 用户实测备注）
  - 需在 WPS 中启用 VBA 环境：专业版/企业版自带；个人版需安装 VBA 支持包，参考[毛老师的安装指引](https://maoyanqing.com/vba-for-wps-office)
  - 核心功能（插入/清单体检/哈希基线/文件夹引用/重命名/断链修复）实测可用
  - WPS 宏安全会拦截子进程，哈希走内置纯 VBA 实现（数 MB 附件的体检耗时约数十秒，属一次性登记成本）
  - **文件夹引用与清单体检在 WPS 端耗时明显长于 Excel**（纯 VBA 哈希约为 `certutil` 的 1/10 速度）——属 WPS 宿主限制（已知软件层面问题），耗时可接受则无需处理
  - **鼎信诺基于 Excel COM 自动化，在 WPS 下无法使用**——归档迁移、看门狗等鼎信诺配套功能仅面向 Excel，WPS 无需也不支持（归档流程请在 Excel 端完成）
  - 菜单自愈/保存归一化等宿主事件特性以 Excel 为准
- 不适用于 Mac / 网页版（链接查看不受限：归档件中的普通超链接在任何表格软件中均可点击）

## 快速开始

**接收 / 复核归档底稿，或负责归档的同事，按以下三步即可：**

1. 从 [GitHub Releases](https://github.com/jasonisbrave/attachlink/releases) 下载 `AttachLink-<版本>.zip`，建议先在 zip 属性页勾选「解除锁定」再解压。
2. 双击 **`AttachLinkSetup.exe`**，按窗口按钮选择**标准安装**；exe 未签名，Windows 可能弹「已保护你的电脑」——点「更多信息 → 仍要运行」。
3. 安装完成后**重启 Excel**，在单元格**右键菜单**选择「插入附件链接（可多选）」，或按 **Ctrl+Shift+A**。

需要归档整个文件夹时，右键选择「插入文件夹引用」。

> [!NOTE]
> 编制人在本机以管理员运行的鼎信诺里插附件，需要标准安装 **+ 方式五**（鼎信诺管理员环境部署）。

> [!TIP]
> 首次使用前建议跑一遍「五分钟验证流程」；正式归档与网盘交付按「归档交付与同步核对 SOP」执行。

## 解决的痛点

| 原方案（非 COM 网页加载项）的缺陷 | 本方案 |
|:---|:---|
| 与鼎信诺 COM 加载项不能共存 | xlam 与 COM 加载项走完全不同的加载通道，互不干扰 |
| 只能用底稿同级的附件文件夹 | 系统文件选择框可浏览**任意位置**；选中后自动归档复制到同级「附件」文件夹 |
| 不能多选，只能逐个添加 | 文件选择框支持 Ctrl / Shift **多选**，按选区顺序逐格插入 |

## 功能一览

1. **插入附件链接**（核心）
   - **前置检查**：底稿同级无「附件」文件夹 → 自动创建并提示；已存在 → 弹窗提示核对（默认同一文件夹每次会话仅提示一次，可配置为每次提示）
   - 未保存的底稿会先提示保存（相对路径需要基准目录）
   - 多选文件 → 自动归档复制，重名时弹窗确认（覆盖 / 保留两者自动重命名 / 跳过）
   - 相对路径超链接逐格插入，显示文件名（默认不含扩展名）
   - 选中单元格不够时自动向下扩展（跳过非空格与合并格）
   - **对话框自动定位到上次选取附件的源目录**（会话级记忆，不再每次落在附件夹重新翻找）
   - **1b. 插入文件夹引用**
     - 选定文件夹**整体复制入附件夹**（保持归档自包含），并插入相对链接；点击即在资源管理器打开
     - 夹内全部文件（含子目录）自动纳入内容基线，体检可检测夹内篡改
     - 断链修复支持文件夹整体重连
   - **1c. 重命名链接显示名**
     - 只改超链接显示文本（应对收到的文件命名不规范/不清晰），不改动文件本身与链接地址
     - 体检、基线、归档迁移均不受影响
     - **支持多选批量**：选区内全部附件链接按行序逐个弹窗（含进度 i/N），留空/取消即停止，已改保留
2. **附件清单 / 体检**：按底稿 sheet 分组编号（如 `货币资金-01`），自动检查每个附件文件是否存在，断链红字标注并汇总；**内容基线校验（SHA-256）**——首次体检把每个附件的内容哈希登记到 `附件\_attachlink_baseline.csv`（随附件夹整体归档迁移/网盘同步），此后体检比对哈希，附件被替换/篡改/同步端同名静默覆盖时红字「■ 内容变更」持续警示（基线不被自动洗白；确为有意替换时删除该文件重新生成清单即重建基线）
3. **断链修复**：指定附件文件夹当前位置，按文件名自动重连（适用于归档件搬家后的场景）
4. **清除链接**：清除选区内的附件链接并恢复单元格字体格式
5. **保存保护**：保存时自动把被 Excel 改写为绝对路径的附件链接归一化回相对路径
6. **归档迁移（批量）**：鼎信诺归档是把底稿另存到新目录、附件夹不在其处理范围，归档件链接仍指回账套。在归档目录打开任一底稿后运行：把账套附件文件夹**整体移动**到归档目录同级（不留副本、避免双份存储），并批量改写归档目录下**所有**底稿的链接为相对地址，归档件自包含
7. **附件版本更新**：附件存在差错需有意替换时，选中该附件链接单元格 → 右键「附件版本更新」→ 选新文件确认。旧文件删除、基线版本 +1 并记录更替时间——体检显示「一致 v2」绿字、清单「更替记录」列显式备注替换动作（审计留痕）。**未经本流程的替换仍红字「■ 内容变更」**，版本更替与篡改由此区分

## 使用入口

**右键菜单结构（高频直达、低频归类）**：

| 菜单路径 | 操作说明 |
|:---|:---|
| **插入附件链接（可多选）** | 插入附件链接；也可按 **Ctrl+Shift+A** |
| **插入文件夹引用** | 插入文件夹引用 |

| **归档** ▸ 归档迁移（批量） | 在**归档目录**（如鼎信诺归档出的「财报底稿」文件夹）中打开任一底稿后运行 |

> 清单每次生成会整表重建（覆盖旧清单及手工修改），归档/核对以当次生成为准。

## 安装 / 卸载

### 按角色选择安装

| 你的角色 | 需要的安装 |
|:---|:---|
| 接收/复核归档底稿（网盘同步、点链接、跑体检） | **标准安装**（方式一）即可，到此为止 |
| 归档人（在归档目录运行「归档迁移（批量）」） | **标准安装**（方式一）即可 |
| 编制人（在本机以管理员运行的鼎信诺里插附件） | 标准安装 **+ 方式五**（鼎信诺管理员环境部署） |

> [!NOTE]
> 普通超链接不依赖本加载项——未安装的同事也能点开附件链接；安装后额外获得体检/清单/修复等能力。

### 方式一：安装器（推荐，发给同事用）

双击 **`AttachLinkSetup.exe`**，按窗口按钮操作：标准安装（接收/归档同事）/ 鼎信诺管理员环境部署（编制机，弹 UAC）/ 两级卸载。正式交付包就两个文件：`AttachLinkSetup.exe` + `README.md`（由 `build\make-exe.ps1` 生成于 `release\AttachLink-<版本>\`，exe 内嵌全部所需文件）。

> [!WARNING]
> - **首次运行提示**：exe 未签名，Windows 可能弹「已保护你的电脑」——点「更多信息 → 仍要运行」
> - **zip 下载后**：建议先在 zip 属性页勾选「解除锁定」再解压（避免解压出的所有文件带阻塞标记）

- 静默参数（自动化/高级用户）：`/install`、`/deploy-elevated`、`/uninstall`、`/uninstall-elevated`、`/selfcheck`
- 安装日志：`%TEMP%\AttachLinkSetup.log`

### 方式二：脚本安装（备用，exe 被安全软件拦截时使用）

完整项目文件夹（或按下方清单裁剪的 zip）解压后，在解压目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1             # 安装
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -Uninstall  # 卸载（仅用户级；机器级见方式五）
```

纯 PowerShell 实现，无未签名 exe 的 SmartScreen/杀软摩擦。

分发清单（运行完整版，按此裁剪 zip）：

| 必须包含 | 用途 |
|:---|:---|
| `README.md` | 用法说明 |
| `dist\AttachLink.xlam` | 预构建安装包 |
| `scripts\setup.ps1` | 安装编排 |
| `scripts\watchdog.ps1`、`scripts\watchdog_launcher.vbs` | 看门狗（方式五部署时由 install-elevated 复制） |
| `build\install.ps1`、`build\install-elevated.ps1` | 安装核心 / 机器级部署 |

- 如需保留「缺产物时现场构建」（B 回退），再附 `build\build.ps1` + `src\AttachLink.bas` + `src\AttachLink.ThisWorkbook.vba`；纯接收版可不带源码（缺 dist 会直接提示包不完整）
- 无需分发：`WORKLOG.md`、`开发交接.md`、`scripts\test-*.ps1`、`src/AttachLinkShim.cs`、`packaging\`、`.git`

### 方式三：脚本安装（本地）

```powershell
powershell -ExecutionPolicy Bypass -File build\install.ps1          # 安装
powershell -ExecutionPolicy Bypass -File build\install.ps1 -Uninstall   # 卸载
```

### 方式四：手动安装（备用）

把 `dist\AttachLink.xlam` 复制到任意目录，在 Excel「文件 → 选项 → 加载项 → 管理：Excel 加载项 → 转到 → 浏览」中选中它并勾选；若打开时提示宏被禁用，把 xlam 所在文件夹加入「信任中心 → 受信任位置」。

> [!TIP]
> 以上任一方式装完**重启 Excel** 即可使用。

### 方式五：机器级看门狗部署（编制机：鼎信诺以管理员运行）

普通双击打开的 Excel 由上面任一方式即可覆盖。但**鼎信诺等审计软件通过 COM 自动化拉起的 Excel 会跳过一切加载项初始化**（OPEN 注册、XLSTART、COM 加载项 OnConnection 全部不触发，本机逐项实测证实）；且鼎信诺常以管理员运行，高完整性进程会忽略 HKCU 的 per-user 注册。此场景需部署**外部看门狗**：

```powershell
# 管理员 PowerShell 中运行一次（无需注销重登，装完立即生效）
powershell -ExecutionPolicy Bypass -File build\install-elevated.ps1
# 卸载
powershell -ExecutionPolicy Bypass -File build\install-elevated.ps1 -Uninstall
```

部署内容：xlam + 看门狗复制到 `C:\Program Files\AttachLink\`；HKLM 受信任位置指向该目录；注册登录计划任务（最高权限常驻，隐藏窗口）。之后鼎信诺打开底稿约 2~4 秒内右键菜单自动出现。看门狗日志：`%TEMP%\AttachLinkWatchdog.log`（装载成功行带 xlam 版本号，便于核对两级同版）。

> [!NOTE]
> **可选：看门狗父进程白名单**（风险收敛，见 [Issue #1](https://github.com/jasonisbrave/attachlink/issues/1)）：部署时加参数 `powershell ... -File build\install-elevated.ps1 -WatchdogParentFilter "sjp7.exe"`，仅附着指定进程拉起的 Excel；默认不启用。
>
> - 修改白名单后需重启看门狗（重跑部署脚本或注销重登）
> - **无参数重部署会删除既有 `watchdog.conf`（恢复不过滤）**——升级时如需保留过滤请带参重跑
> - 本机同时存在新旧两级看门狗时，旧版不受过滤约束——**过滤要完全生效必须两级同步部署**（日常升级本来也要求两级分别更新）

> [!WARNING]
> **升级注意（两级分别更新）**：新版发布时，已做过方式五部署的机器必须**重跑方式一/三（用户级）+ 重跑本脚本（机器级）**——只跑用户级会让鼎信诺继续用 Program Files 里的旧版。本脚本结束时会输出与 dist 的 SHA-256 核对结果，不一致即说明机器级落后了。

> [!NOTE]
> 前置条件：先以方式一~三完成普通用户级安装（看门狗只负责鼎信诺场景，日常 Excel 由用户级安装覆盖）。

## 与鼎信诺共存

### 三个机制并存，加载通道相互独立

| 机制 | 归属 | 存在位置 |
|:---|:---|:---|
| 鼎信诺 COM 加载项 | Excel 应用 | 系统 COM 组件 |
| 鼎信诺底稿内嵌宏 | 底稿文件 | 文件内部 VBA 工程 |
| AttachLink.xlam | Excel 应用 | 外置加载项文件，不进底稿 |

> [!NOTE]
> 注意：保存事件层面与鼎信诺/底稿内嵌宏同处一条保存链，本加载项的保存归一化为窄范围幂等操作——只精确改写本工具插入的附件链接（完整父目录比对），不依赖与鼎信诺保存宏的先后顺序。

- 鼎信诺归档剥离的是**底稿文件内部**的宏与数据库连接，xlam 在外部，剥离不到，归档件无任何残留。
- 插入的是**普通超链接**（工作表内容），不是公式也不是宏——即使归档时公式被值化，链接依然有效（这正是选普通超链接而非 `=HYPERLINK()` 公式的原因）。

### 五分钟验证流程（建议首次使用前跑一遍——覆盖「归档件自包含」全链）

1. 新建测试文件夹，放入一张测试底稿并保存
2. 用本加载项插入 1–2 个附件链接，确认：附件文件夹自动生成、文件已复制、链接可点击
3. 按鼎信诺正常流程归档（「保留公式链接」勾选与不勾选各试一次）——归档目录中的底稿链接此时仍指回账套（正常现象）
4. 在归档目录打开任一底稿，运行右键**「归档迁移（批量）」**：附件夹整体移动过来、全部底稿链接改写为相对地址
5. 运行**「附件清单 / 体检」**：应全部「正常/一致」绿字，并在附件夹内生成 `_attachlink_baseline.csv` 基线
6. **把整个归档文件夹（含底稿与附件夹）移动到新目录**，再点链接——应全部可打开（证明归档件自包含、与位置无关）
7. 故意改动一个附件内容再体检 → 出现红字「■ 内容变更」即篡改检测生效；再用右键「**附件版本更新**」走一遍受控更替 → 体检变「一致 v2」绿字且清单「更替记录」列留痕——版本更替与篡改的区分即验证完成

> [!IMPORTANT]
> **注意**：归档交付时保持「底稿 + 附件文件夹」同级结构整体打包（zip 内保留目录），相对链接在解压后有效。

### 归档交付与同步核对 SOP（发送方 → 网盘 → 接收方）

**发送方**：

1. 鼎信诺归档 → 在归档目录运行「归档迁移（批量）」
2. **运行一次「附件清单 / 体检」**——这一步生成内容基线 `_attachlink_baseline.csv` 并确认无断链（跳过此步，接收方首检会把收到的现状登记为基线，无法发现传输前/传输中的替换）
3. 把**整个归档目录**（全部底稿 + `附件\` 完整文件夹，含基线文件）上传企业网盘目标文件夹——多个归档各自独立成目录，**不要**合并进同一附件夹

**接收方**：

1. 在企业网盘**本地同步目录**中操作（网页预览/只下载底稿不行——附件夹必须同步到位）
2. 打开底稿点附件链接核对
3. 运行「附件清单 / 体检」：基线比对，全部「一致」即归档件完整可信
4. 出现红字「■ 内容变更」→ **反馈发送方核实**，不得自行删除基线文件「洗白」；确为有意替换的，由业务负责人确认后删除基线重建

### 自动化拉起场景与外部看门狗（根因记录）

**根因（本机逐项实测，详见 WORKLOG）**：鼎信诺通过 `CreateObject` 拉起 Excel 时，Excel 跳过 `.xlam`（OPEN 注册）、`XLSTART`、COM 加载项 `OnConnection` **三条自动初始化路径**；`AddIns` 集合中 `Installed=True` 只反映登记状态、不代表已装载。因此装载必须来自 Excel 进程**外部**。

**看门狗机制**（`scripts\watchdog.ps1`，微软文档化的 Office Native OM 附着通道，不依赖 ROT、不注入）：

```
普通双击打开的 Excel ──► xlam 经 OPEN 注册自动装载（原有机制，正常工作）
鼎信诺拉起的 Excel   ──► 看门狗（外部 PowerShell 常驻）检测 EXCEL7 文档窗口
                          └► AccessibleObjectFromWindow 取 Application
                          └► Workbooks.Open(xlam) 强制装载（IsAddin 工作簿，
                          │   无可见窗口、不扰动用户；已装载时为 no-op）
                          └► Application.Run('AttachLink_Initialize') 补初始化（幂等）
                          └► 验证右键菜单 Tag 在位，未在位下轮重试
```

时序上恰好适配：零工作簿的自动化实例没有 EXCEL7 窗口、不会被附着；鼎信诺打开底稿（出现文档窗口）后下个周期（默认 2 秒）自动完成装载。

**提权注意事项**：鼎信诺以管理员运行时，Excel 为高完整性进程——

- 忽略 HKCU 的 per-user 注册（含 COM 类与受信任位置保障），必须走 **HKLM**；
- 看门狗本身需以 `RunLevel=Highest` 计划任务常驻（高完整性可附着中/高完整性双方，反之被 UIPI 拒绝）；
- **安全要求：提权进程不得从用户可写目录装载代码**，故机器级部署把 xlam 放在管理员控制的 `C:\Program Files\AttachLink\`，HKLM 受信任位置仅指向该目录（`AllowSubFolders=0`）。

## 已知限制

- 一个单元格最多一个超链接（目标格已有链接时会被新链接替换）；清单表每次整表重建（非本工具生成的同名「附件清单」表会被拒绝覆盖并提示）
- 「附件版本更新」暂不支持文件夹引用（需清除重插并重建基线，见 [FAQ.md](FAQ.md)）
- **文件夹基线语义**：校验**夹内现存文件**的内容一致性与登记完整性；不检测的缺失性变化包括**文件被删除、基线孤儿键、文件与文件夹类型互换**（现存同名文件的内容替换会检测；完整目录清单以归档交付包为准）
- 「预览」功能有意不做（系统级 QuickLook 类应用已覆盖，避免工具臃肿——2026-11-20 决策）
- 底稿必须已保存（有基准路径）才能插入
- 编制端（加载项功能）支持 Windows 桌面版 Excel 与 WPS 表格（v1.3.0 起，需 VBA 环境）；编制端不支持 Mac/网页版。归档件查看（点链接）不受限——任何表格软件均可打开归档件并点击普通超链接
- 宏被全面禁用且无法配置受信任位置的环境不适用
