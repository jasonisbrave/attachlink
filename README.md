# AttachLink —— 审计底稿附件链接加载项

[![Release v1.6.0](https://img.shields.io/badge/Release-v1.6.0-217346)](https://github.com/jasonisbrave/attachlink/releases)

![WPS 支持 v1.3.0+](https://img.shields.io/badge/WPS-%E6%94%AF%E6%8C%81%20v1.3.0%2B-E8380D)

Excel 加载项（`.xlam`，走「Excel 加载项」通道，**不注册 COM**），用于在审计底稿中批量插入附件超链接：

> 多选文件 → 自动归档复制到底稿同级「附件」文件夹 → 以**相对路径**插入超链接

与鼎信诺 COM 加载项**可共存**；宏全部在加载项内，**底稿文件保持无宏**，不影响鼎信诺读取与归档剥离。

> [!IMPORTANT]
> **正式分发渠道：[GitHub Releases](https://github.com/jasonisbrave/attachlink/releases)**（下载 `AttachLink-<版本>.zip`，发布说明内附 SHA-256 校验值；企业网盘仅作归档同步载体，不作安装包分发）。

## 环境要求

- Windows + 桌面版 Excel 2010 及以上；PowerShell 5.1+
- **WPS 表格亦支持（v1.3.1 起菜单为 4 顶项浓缩版）**
  - 仅在 WPS **「表格」**组件中实现，**「智能表格」中无法使用**（2026-11-21 用户实测备注）
  - 需在 WPS 中启用 VBA 环境：专业版/企业版自带；个人版需安装 VBA 支持包，参考[毛老师的安装指引](https://maoyanqing.com/vba-for-wps-office)
  - 核心功能（插入/清单体检/哈希基线/文件夹引用/重命名/断链修复）实测可用
  - 哈希（SHA-256）走系统原生实现（v1.6.0 起，与 Excel 同一条路径，约 300 MB/秒）；WPS 拦截子进程，`certutil` 与纯 VBA 实现只作回退
  - v1.6.0 之前 WPS 下插入 / 底稿引用 / 体检明显慢于 Excel（当时 WPS 只能用纯 VBA 算哈希，实测约 0.21 MB/秒：插入 5 MB 附件约 23 秒、体检 50 MB 约 4 分钟），现已修复——同一场景约 0.02 ~ 0.2 秒
  - **鼎信诺基于 Excel COM 自动化，在 WPS 下无法使用**——归档迁移、看门狗等鼎信诺配套功能仅面向 Excel，WPS 无需也不支持（归档流程请在 Excel 端完成）
  - 菜单自愈/保存归一化等宿主事件特性以 Excel 为准
- **Excel 与 WPS 同时安装的机器（v1.4.3 起）**
  - **看门狗只附着 `EXCEL.EXE`**，不再向 WPS 表格注入加载项。旧版会让 WPS 卡在「正在打开文档…」或反复弹「名为"AttachLink.xlam"的文档已经打开」
  - **升级时两级一并更新**：v1.4.2 及更早版本升级时，重新运行安装器点「一键安装」即可（加载项与看门狗一并更新）；只点了「仅安装加载项」的机器，Program Files 里的旧版看门狗仍在运行，安装日志会提示补做部署。v1.5.0 起也可以用安装器的「检查更新 → 一键更新」完成升级（更新前同样要先关闭 Excel 与 WPS 表格）
  - **WPS 菜单取决于 VBA 环境**：WPS 表格启动时会沿用 Excel 的加载项注册：有 VBA 环境时 AttachLink 自动加载、出现右键菜单；未装 VBA 环境的 WPS 没有菜单（编制请在 Excel 中完成），归档件点链接查看不受影响
  - **判断 WPS 是否有 VBA 环境**：看 Windows「应用和功能」里有没有「VBA (xxxx.xx)」项，或在 WPS 表格里按 Alt+F11 看能否打开 VBA 编辑器——**不要**以 WPS 安装目录下有没有 `vbe7.dll` 为准（该文件不在那里）
  - 升级 / 重装前请同时关闭 WPS 表格（它可能已加载 AttachLink 并占用文件；安装器检测到时会给出对应提示）
- 不适用于 Mac / 网页版（链接查看不受限：归档件中的普通超链接在任何表格软件中均可点击）

## 快速开始

**接收或复核归档底稿、负责归档的同事，请按以下三步操作：**

1. 从 [GitHub Releases](https://github.com/jasonisbrave/attachlink/releases) 下载 `AttachLink-<版本>.zip`，建议先在 zip 属性页勾选「解除锁定」再解压。
2. 双击 **`AttachLinkSetup.exe`**，点 **「一键安装」**；中途弹出管理员授权时点「是」。
   exe 未签名，Windows 可能弹「已保护你的电脑」——点「更多信息 → 仍要运行」。
3. 安装完成后**重启 Excel**，在单元格**右键菜单**选择「插入附件链接（可多选）」，或按 **Ctrl+Shift+A**。

需要归档整个文件夹时，右键选择「插入文件夹引用」。

> [!NOTE]
> 「一键安装」= 启用加载项 + 部署鼎信诺环境，编制人在本机以管理员运行的鼎信诺里插附件也一并就绪。
>
> **不用鼎信诺、或没有管理员权限**的同事：展开窗口底部的「更多选项」，选「仅安装加载项」。授权被取消时加载项同样已装好，日常 Excel 可直接使用。

> [!TIP]
> 首次使用前建议跑一遍「五分钟验证流程」；正式归档与网盘交付按「归档交付与同步核对 SOP」执行。

## 解决的痛点

| 原方案（非 COM 网页加载项）的缺陷 | 本方案 |
|:---|:---|
| 与鼎信诺 COM 加载项不能共存 | xlam 与 COM 加载项走完全不同的加载通道，互不干扰 |
| 只能用底稿同级的附件文件夹 | 系统文件选择框可浏览**任意位置**；选中后自动归档复制到同级「附件」文件夹 |
| 不能多选，只能逐个添加 | 文件选择框支持 Ctrl / Shift **多选**，按选区顺序逐格插入 |

## 功能一览

1. **插入附件链接**（核心）
   - **前置检查**：底稿同级无「附件」文件夹 → 自动创建并提示；已存在 → 弹窗提示核对（默认每个插入入口对同一文件夹每次会话各提示一次，可配置为每次提示）；三个插入入口（附件 / 文件夹 / 底稿引用）都在弹出文件选择框**之前**完成这项检查
   - 未保存的底稿会先提示保存（相对路径需要基准目录）
   - 多选文件 → 自动归档复制；同名文件按内容判断（同内容复用、异内容自动另存，见下方第 9 条），仅无法计算哈希时才弹窗确认
   - **文件名含 `#` 时在复制之前整批拒绝并列出清单**——Excel 会把链接地址在 `#` 处截断，链接必断且无法修复，请先重命名
   - 相对路径超链接逐格插入，显示文件名（默认不含扩展名）
   - 选中单元格不够时自动向下扩展（跳过非空格与合并格）
   - 目标格所在工作表受保护时该条按失败处理并写明原因（文件已复制到附件夹并登记基线，撤销保护后在未保护的单元格重试会直接复用），其余条目照常
   - **对话框自动定位到上次选取附件的源目录**（会话级记忆，不再每次落在附件夹重新翻找）
   - **1b. 插入文件夹引用**
     - 选定文件夹**整体复制入附件夹**（保持归档自包含），并插入相对链接；点击即在资源管理器打开
     - 夹内全部文件（含子目录）自动纳入内容基线，体检可检测夹内篡改
     - 附件夹里已有同名文件夹时不再逐文件合并覆盖——逐文件比对（源 ↔ 副本 ↔ 内容基线），全部一致才直接复用；任一文件不一致、缺失、副本与基线不符，或同名路径其实是个文件 → 整个文件夹另存为「名(2)」并链接到新副本，现有副本的任何文件都不会被改动，汇总里明示
     - 断链修复支持文件夹整体重连
   - **1c. 重命名链接显示名**（入口：右键「附件管理 ▸ 重命名链接显示名」）
     - 只改超链接显示文本（应对收到的文件命名不规范/不清晰），不改动文件本身与链接地址
     - 体检、基线、归档迁移均不受影响
     - **支持多选批量**：选区内全部附件链接按行序逐个弹窗（含进度 i/N），留空/取消即停止，已改保留
   - **1d. 插入底稿引用**
     - 在单元格中插入指向同项目其他底稿**指定工作表**的超链接（跨底稿交叉索引）
     - 目标底稿复制入附件夹（自包含原则），链接指向附件夹内副本；附件夹已有同名副本时，内容一致才静默复用，不一致则弹窗确认（防止误引用旧版或异源的同名底稿）
     - 打开目标底稿、读取工作表列表时启用三重防护（禁宏 / 禁外部链接刷新 / 禁弹窗）；表名含空格、单引号等特殊字符时，`SubAddress` 按 Excel 规则转义
     - 与「插入附件链接」同一套附件文件夹前置检查，且同样在入口、选择目标底稿之前完成（v1.6.0 起；提示文案说明归档的是底稿副本）
2. **附件清单 / 体检**
   - 按底稿 sheet 分组编号（如 `货币资金-01`），自动检查每个附件文件是否存在，断链红字标注并汇总
   - 清单表受保护、或工作簿结构受保护且没有清单表时，给出明确提示（先撤销保护），不会再无原因失败
   - **内容基线校验（SHA-256）**：每个附件的内容哈希登记到 `附件\_attachlink_baseline.csv`（随附件夹整体归档迁移/网盘同步）；v1.5.0 起插入附件时即登记，此前插入的附件在首次体检时补登记，体检时比对哈希，附件被替换/篡改/同步端同名静默覆盖时红字「■ 内容变更」持续警示（基线不被自动洗白；确为有意替换时删除该文件重新生成清单即重建基线）
3. **断链修复**：指定附件文件夹当前位置，按内容基线可信重连（适用于归档件搬家后的场景，见下方第 10 条）
4. **清除链接**：清除选区内的附件链接并恢复单元格字体格式
5. **保存保护**：保存时自动把被 Excel 改写为绝对路径的附件链接归一化回相对路径；链接地址里的正斜杠（`附件/a.pdf`，Excel 在某些情况下会自动改写）同样能正常识别与检查
6. **归档迁移（批量）**
   - 鼎信诺归档是把底稿另存到新目录、附件夹不在其处理范围，归档件链接仍指回账套
   - 在归档目录打开任一底稿后运行：把账套附件文件夹**整体移动**到归档目录同级（不留副本、避免双份存储），并批量改写归档目录下**所有**底稿的链接为相对地址，归档件自包含
   - 移动失败的文件，其链接保持原地址不改写，并在汇总里单列（不是漏报）
7. **附件版本更新**
   - 附件存在差错需有意替换时，选中该附件链接单元格 → 右键「附件管理 ▸ 附件版本更新」→ 选新文件确认
   - 旧文件将被替换（先备份后替换，失败保留原附件：新文件经同目录临时文件中转，替换失败时原附件自动恢复、内容基线不变，只有新文件确认落盘后才移除备份）、基线版本 +1 并记录更替时间——体检显示「一致 v2」绿字、清单「更替记录」列显式备注替换动作（审计留痕）
   - **未经本流程的替换仍红字「■ 内容变更」**，版本更替与篡改由此区分
   - 体检、插入、修复、删除、迁移进行中不能发起版本更新（反之亦然），避免并发写坏内容基线
8. **附件删除（删链接+文件）**
   - 删除选区内全部附件链接；弹窗按文件 / 文件夹 / 断链分类列明清单，确认后**连带删除附件夹内对应文件 / 文件夹，并清除基线条目**（文件夹连带全部后代键）
   - 先删链接、确认成功后再删文件；链接删不掉（工作表受保护）时文件保留并在汇总里写明
   - 同一文件还有其它链接在引用时，会先列出这些链接并要求二次确认
   - 链接清除使用 `ClearHyperlinks`，保留单元格边框 / 填充。

> [!WARNING]
> **破坏性操作，三重约束**：
> - 仅允许处理当前底稿附件夹内目标；越界则整体拒绝、零删除
> - **不可撤销**
> - 四类失败（文件 / 链接 / 清理 / 基线）独立计数、如实汇总；锁定文件、保护工作表等部分失败绝不虚报成功

9. **插入即登记（v1.5.0）**
   - 附件归档同时写入内容基线（SHA-256）
   - 附件夹已有同名文件时，只有「当前副本、内容基线、新文件」三者 SHA-256 完全一致才直接复用、不重复复制
   - 当前副本与其内容基线不一致（体检会标红）时**不复用**——新文件另存「名(n).ext」并建立自己的基线，汇总里明示，旧基线不被改写；其余同名异内容同样自动另存——不覆盖原文件、不弹窗打断
   - 汇总如实列出复用与另存明细。
10. **可信断链重连（v1.5.0）**：断链修复按内容哈希分层判定
    - 本附件夹已有同内容副本仅改指不复制；同名同内容直接重连；同名异内容拒绝误连并尝试按内容找回（候选唯一时以原文件名落回）
    - 无基线按名重连并标注「未校验」、当场登记建立身份
    - 文件夹链接：本附件夹**没有**同名文件夹时，核对修复来源与内容基线后复制，**已有**同名文件夹时逐文件比对，全部一致才只改指链接、不复制本地文件（本地多出的文件不算冲突，会在汇总里说明）
    - 子目录里的断链只按「子目录\文件名」完整路径的内容基线认定，不借用根目录同名文件的基线
    - 链接路径异常（如 `附件\..\某文件`）规范化后落在附件夹之外的不处理、不复制、不改指，请人工核对链接地址
    - 汇总里「未校验」类排在最前，存在未校验、冲突或失败时结果框用警示图标。
11. **基线安全读写（v1.5.0）**
    - 基线写入先写临时文件并回读校验，再备份后替换；损坏或含更新版本字段的基线绝不覆盖
    - 基线文件只要有一行损坏、或被其它程序独占锁定无法读取，插入附件、插入文件夹引用、插入底稿引用、断链修复都会在**写入任何文件之前停止**，提示「失败：基线文件损坏或无法读取」——这是有意为之：读取失败不等于没有基线，按文件名强行重连会绕过附件身份校验，请先人工核对或重建基线
    - 体检遇损坏基线只查存在性、内容列红字「■ 基线损坏」并明确提示人工处置；基线为更新版本格式（本版只读）时，已有登记仍用于校验，本次新登记不写入，汇总里说明。
12. **体检增强与保存提醒（v1.5.0）**
    - 内容哈希按文件去重：同一次体检同一文件只算一次 SHA-256，大附件夹明显提速；状态栏实时显示「附件体检 i/N」
    - 体检中按 **Esc** 可取消——清单 A1 红字注明已处理 N/M，基线不变
    - 保存归一化失败可见：保存后状态栏提醒；之后在同一 Excel 会话里于该工作簿中右键时再提醒（v1.6.4 起，原先是在重新打开它时提醒）；体检 E 列红字「正常（■ 绝对路径）」并计数，解除保护后 Ctrl+S 即可自动修正。
13. **健康检查（v1.5.0，安装器）**：安装后随时可做一次只读体检，确认两级部署、启用登记、受信任位置与看门狗心跳都正常——见下方[「健康检查」](#健康检查)小节。
14. **检查更新 / 一键更新（v1.5.0，安装器）**：安装器自动下载新版本安装包、SHA-256 校验通过后完成升级——见下方[「检查更新与一键更新」](#检查更新与一键更新)小节。

## 使用入口

**右键菜单结构（高频直达、低频归类；v1.6.0 起「归档迁移」提级到一级，「归档」子菜单更名为「附件管理」）**：

| 菜单路径 | 操作说明 |
|:---|:---|
| **插入附件链接（可多选）** | 插入附件链接；也可按 **Ctrl+Shift+A** |
| **插入文件夹引用** | 插入文件夹引用 |
| **插入底稿引用** | 插入指向其他底稿**指定工作表**的引用；目标底稿副本存入附件夹，保持自包含 |

### 方式一：安装器（推荐，发给同事用）

双击 **`AttachLinkSetup.exe`**，点 **「一键安装」**（v1.4.3 起为默认操作）：先启用加载项，再部署鼎信诺环境，中途弹一次管理员授权。v1.5.0 起，一键安装成功后会**自动做一次健康检查**（只读），结论并入结果——全部正常时无感；有需留意 / 异常项时结果会列出并给出处置提示（点「更多选项 → 健康检查」可随时重跑，见下方「健康检查」小节）。

### 方式五：机器级看门狗部署（编制机：鼎信诺以管理员运行）

普通双击打开的 Excel，上面任一安装方式即可覆盖。但**鼎信诺等审计软件通过 COM 自动化拉起的 Excel 会跳过一切加载项初始化**（OPEN 注册、XLSTART、COM 加载项 OnConnection 全部不触发，本机逐项实测证实）；且鼎信诺常以管理员运行，高完整性进程会忽略 HKCU 的 per-user 注册。此场景需部署**外部看门狗**：

```powershell
# 管理员 PowerShell 中运行一次（无需注销重登，装完立即生效）
powershell -ExecutionPolicy Bypass -File build\install-elevated.ps1
# 单独卸载机器级（兼容保留；通常无需单独运行，详见下方「一键卸载」）
powershell -ExecutionPolicy Bypass -File build\install-elevated.ps1 -Uninstall
```

部署内容：

- xlam + 看门狗（`AttachLink.Watchdog.exe`，预编译的 .NET 程序；`watchdog.ps1` 一并部署，只作回退）+ 无窗口启动器（`AttachLink.WatchdogLauncher.exe`）复制到 `C:\Program Files\AttachLink\`（部署时顺带清掉旧版留下的 `watchdog_launcher.vbs`）
- HKLM 受信任位置指向该目录
- 注册计划任务（最高权限，动作直接是无窗口启动器——没有控制台窗口）。任务带两个触发器：登录即启动；另有一个时间触发器每 5 分钟重复，作为兜底——任务不在运行时（启动器被结束，或它放弃之后），下一次重复会重新启动
- 看门狗异常退出（非 0）后由启动器 10 秒后拉起；连续 3 次没能稳定运行（每次不足 60 秒）才放弃——启动器以看门狗的退出码结束，该值成为计划任务的上次运行结果，其动作写进看门狗日志（「启动器:」开头的行）
- 启动器旁边有 `AttachLink.Watchdog.exe` 就用它；需要退回 PowerShell 版时，以管理员运行 `build\install-elevated.ps1 -LegacyPowerShell`（不再部署 .NET 看门狗，并删掉机器级目录里已有的那一份）

之后鼎信诺打开底稿约 2~4 秒内右键菜单自动出现。看门狗日志：`%TEMP%\AttachLinkWatchdog.log`（装载成功行带 xlam 版本号，便于核对两级同版；周期行只在 EXCEL7 窗口数变化或每 30 秒心跳时记录）。

> [!NOTE]
> **看门狗只附着 Microsoft Excel**（v1.4.3 起）。具体规则如下：
>
> - **宿主校验**：按窗口类名找到 `EXCEL7` 后，先校验窗口所属进程必须是 `EXCEL.EXE`；否则记一行「跳过 … 仅附着 EXCEL.EXE」，且不做任何调用。WPS 表格为兼容自动化同样使用 `XLMAIN` / `EXCEL7` 窗口类名，旧版看门狗会把加载项注入 WPS，致其卡死或反复弹「同名文件已打开」。
> - **xlam 缺失时暂停**：xlam 文件缺失（升级 / 卸载进行中）时，看门狗暂停附着，不向任何宿主发起调用。
> - **附着后释放引用**：每次附着结束即释放对宿主的对象引用。旧版会一直持有引用，被附着过的 Excel 关闭后，进程可能长时间残留在内存里不退出（重新打开会连回旧进程，旧版加载项仍在）；v1.4.3 起看门狗用完即释放。
> - **已在位即不动**：加载项已随 Excel 正常启动装载的会话，看门狗确认右键菜单与加载项工作簿都在位后，不再重复装载。菜单在位而加载项并不在位（Excel 命令栏缓存里残留的「死菜单」，点击会报宏不可用）时，看门狗先删掉残留菜单再重新装载，该实例正常退出后缓存随之清干净。
> - **只附着看得见的会话**（v1.6.2 起）：`Application.Visible` 为假的隐藏 Excel——各类工具、脚本在后台拉起的实例，以及鼎信诺归档时另起的那个——不再被装载，看门狗只留意它何时变可见，变了再按常规处理。AttachLink 是给人右键用的，看不见的会话用不上它，往里装只有风险。最小化的窗口算可见。宿主里已有同名加载项时，不再打开第二份。
> - **隐藏窗口不处理**：隐藏的文档窗口（加载项自身的窗口、被隐藏的工作簿）不作为处理对象。Excel 刚开始退出的瞬间，若看门狗恰好对加载项自身的窗口再执行一次装载，实例会退不掉（受控实验中 12 次全部残留），本版予以规避。看门狗在打开加载项、执行初始化之前，都会确认目标窗口仍然存在。

> [!NOTE]
> **可选：看门狗父进程白名单**（风险收敛，见 [Issue #1](https://github.com/jasonisbrave/attachlink/issues/1)）：部署时加参数 `powershell ... -File build\install-elevated.ps1 -WatchdogParentFilter "sjp7.exe"`，仅附着指定进程拉起的 Excel；默认不启用。
>
> - 修改白名单后需重启看门狗（重跑部署脚本或注销重登）
> - **一键安装、一键更新、重复部署默认保留已有的 `watchdog.conf`**（不会清掉已有的加固配置）；需要清除时在管理员 PowerShell 运行 `powershell -ExecutionPolicy Bypass -File build\install-elevated.ps1 -ClearWatchdogParentFilter`
> - 本机同时存在新旧两级看门狗时，旧版不受过滤约束——**过滤要完全生效必须两级同步部署**（日常升级本来也要求两级分别更新）

> [!WARNING]
> **升级注意（两级分别更新）**：新版发布时，已做过方式五部署的机器必须**重跑方式一/三（用户级）+ 重跑本脚本（机器级）**——只跑用户级会让鼎信诺继续用 Program Files 里的旧版。本脚本结束时会输出与 dist 的 SHA-256 核对结果，不一致即说明机器级落后了。
>
> **v1.4.2 及更早版本的看门狗会向 WPS 表格注入加载项**：装了 WPS 的机器升级到 v1.4.3 及以上后，务必重跑本脚本更新看门狗（用户级安装结束时会提示）。用安装器的同事再点一次「一键安装」即完成两级更新。

> [!NOTE]
> 前置条件：先以方式一~三完成普通用户级安装（看门狗只负责鼎信诺场景，日常 Excel 由用户级安装覆盖）。

### 一键卸载（v1.4.2+，推荐）

可通过安装器 exe 的「一键卸载」按钮，或运行以下命令：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -Uninstall
```

一键卸载会先做预检、再按事实核验，步骤如下：

1. **预检**：有 Excel 正在运行，或加载项文件正被占用（WPS 表格、其它打开了该加载项的程序）时**不会卸载**，并提示先关闭
2. 执行用户级卸载：清理加载项注册与加载项列表登记、受信任位置及 APPDATA 副本
3. 检测机器级足迹（计划任务 / Program Files / HKLM 信任位置）
4. 检测到机器级足迹时，弹**一次** UAC，一并卸载看门狗
5. **按事实逐项核验**：加载项副本、受信任位置（16.0 / 15.0 / 14.0 三个 Office 版本）、旧 COM 引导器登记、加载项列表登记、计划任务、部署目录——只要有残留，就列出清单并显示「卸载未完全成功」，不会再出现「显示卸载完成、实际有残留」

对于已在运行的 Excel 会话，右键菜单会保留到该会话关闭；重启 Excel 后不再出现。

- **卸载后重新安装失败**（提示「加载项注册失败……加载项注册后未处于启用状态」）：通常是 v1.4.3 及更早版本安装器的问题，升级到 v1.4.4 及以上后重新「一键安装」。
- **卸载未完全成功**：按结果里列出的残留清单处理（常见原因是文件被占用或受信任位置旧键删不掉）；先关闭所有 Excel / WPS 表格后重新卸载，仍失败则按清单手动处理。

以上两项的详细说明见 [FAQ「安装与菜单」](FAQ.md#安装与菜单)。

命令行退出码（`/uninstall`、`/uninstall-elevated`、`/install-all`）：

| 退出码 | 含义 |
|---|---|
| 0 | 卸载完成且核验无残留 |
| 2 | 卸载未执行：Excel 正在运行，或加载项文件被占用 |
| 8 | 机器级看门狗有残留，或管理员授权被取消 |
| 9 | 只有加载项列表（OPEN / Add-in Manager）登记未能完全清理 |
| 10 | 用户级有残留（副本 / 受信任位置 / 旧引导器等，清单见日志） |

`/uninstall-elevated` 非 0 = 机器级有残留；`/install-all` 用别的管理员账户授权时显示「加载项已安装，鼎信诺环境未部署（使用了其他管理员账户授权）」，加载项本身已装好。

### 健康检查

安装完成后可随时做一次只读体检，确认两级部署、启用登记、受信任位置与看门狗心跳都正常。**只读**：不写注册表、不改文件、不启停计划任务、不弹 Excel。

- 图形界面：安装器里展开「更多选项」→ 点「健康检查」。
- 静默命令行：`AttachLinkSetup.exe /healthcheck`（退出码：0 = 无异常项；10 = 发现异常项；1 = 检查脚本自身出错）。注意「需留意」项不改变退出码。
- 不经安装器直接跑：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\healthcheck.ps1`（仅开发者/IT，需要仓库文件在场）。

状态含义与处置：

| 状态 | 含义 | 处置 |
|---|---|---|
| 【通过】 | 该项正常 | 无需处理 |
| 【留意】 | 可用但有隐患（如两级副本版本不一致） | 按提示重新「一键安装」覆盖 |
| 【异常】 | 该项失效（文件缺失 / 登记被禁用 / 看门狗无心跳等） | 按【异常】行附带的处置提示操作；多数重新「一键安装」即修复 |
| 【跳过】 | 机器级各项在未部署时显示（不使用鼎信诺属正常） | 无需处理；需要鼎信诺时重新「一键安装」 |
| 【信息】 | 诊断快照（日志规模、OPEN 序列、安装日志结论） | 排障时对照，无需处理 |

判读时注意：

- **计划任务状态**：计划任务直接运行无窗口启动器（`AttachLink.WatchdogLauncher.exe`），看门狗运行期间显示 Running 是正常的；显示 Ready 表示任务当前没有在运行（看门狗不在运行），若刚在任务计划程序里结束过任务，最多 5 分钟后重复触发会重新启动。在任务计划程序里只点「结束」，任务最多 5 分钟后会自己回来；要真正停下请禁用任务（卸载脚本会直接注销任务）。日志里「启动器:」开头的行是启动器写的（看门狗自身写其余行）。「上次运行结果」显示 `0x800710E0`（操作员或管理员拒绝了请求）同样正常：看门狗运行满一个重复间隔后，重复触发发现任务已在运行、新实例被忽略，留下的就是这个值；其他非 0 值才表示启动器已放弃。
- **附着失败重试**：日志里的「附着失败（退避重试）」等自愈类重试，少量出现属正常瞬态（显示【信息】）；v1.6.1 起同一个窗口按退避重试（2、4、8、16 秒，封顶 30 秒），这类行会明显减少——若最近 200 行内这类重试达到 20 条以上、或 10 条以上且最早与最晚一条跨越超过 10 分钟，健康检查会给出【留意】「看门狗持续附着失败」，提示目标 Excel 实例可能长期无响应、或看门狗反复被打断，请按处置提示排查，无法定位时把看门狗日志发给维护者。
- **登录触发器**：被禁用（Enabled=False）时任务虽存在但永远不会随登录触发（【留意】，任务配置不正常）。
- **重复兜底**：任务须另有一个带重复的时间触发器（每 5 分钟）。没有这个触发器，或重复只挂在登录触发器上（那样要到下次登录才生效，本次登录里没有兜底），健康检查给出【留意】并提示重新「一键安装」。
- **计划任务账户**：登记的账户不是当前登录用户时给出【留意】（任务只在该账户登录时启动）。
- **查询失败**：计划任务查询失败（权限不足、服务不可用等）时机器级部署与任务两项显示「无法确认」（【留意】）而非误判「未部署」，其余依赖项跳过并注明「无法确认」。

### 检查更新与一键更新

v1.5.0 起安装器提供「检查更新」与「一键更新」。安装器右下角点「检查更新」；发现新版本时日志区上方出现提示条，点「一键更新」即可——安装器会自动下载新版本的安装包，**经 SHA-256 校验通过后**交给新版本安装器接着完成安装（相当于自动做一次「一键安装」）。

- **需要联网**。国内直连 GitHub 不稳定，安装器内置了公共加速镜像列表，会依次尝试、自动回退（镜像失效时不影响更新，只是换下一个地址）。清单与安装包的下载中**途断流**（超时、连接重置、传输不完整）会自动换下一个来源，全部来源都失败才报错。
- **信任模型**：更新清单（latest.json）由发布私钥签名（RSASSA-PKCS#1 v1.5 + SHA-256），安装器用内嵌的发布公钥验签，通过后才信任清单中的下载地址与 SHA-256 哈希；加速镜像只负责传输，内容被篡改或损坏会被验签拒绝并自动换下一个来源。本地演示模式（`--manifest-url` 指向回环地址）放宽地址门槛但同样验签，没有旁路。若所有来源的清单都验签失败，界面会提示「清单签名校验失败：不是 AttachLink 发布密钥签发」，请稍后重试或手动到 Releases 下载。
- **镜像缓存**：加速镜像返回「没有新版本」时，安装器会在总时限内用 GitHub 直连复核一次，避免镜像缓存旧清单导致误报「已是最新」；直连不可达时沿用镜像结果，并提示「可能有缓存延迟，可稍后再查或到 Releases 页面手动下载」。
- **更新前请先关闭 Excel（含鼎信诺）和 WPS 表格**，与「一键安装」的要求相同。
- 更新过程会**弹出一次管理员授权**（安装加载项与鼎信诺环境时需要），请点「是」。
- 下载包经过 **SHA-256 校验**，校验不通过不会安装（自动删除半成品）。
- 更新失败时可稍后重试，或手动到 [Releases 页](https://github.com/jasonisbrave/attachlink/releases) 下载新版本安装包，解压后直接运行安装器。
- 命令行（自动化/高级用户）：`AttachLinkSetup.exe /check-update`（退出码 0=已是最新，20=有新版本，21=检查失败）、`/update`（退出码 0=已交接或已是最新，22=失败），`/update` 可加 `--update-dry-run` 只下载校验不安装。
- **更新交接（安全替换）**：新安装器先把自身复制到旧文件同目录的临时文件并做 SHA-256 内容校验，通过后才把旧文件改名为随机后缀备份、临时文件就位；任一步失败旧文件保持原样。替换失败会自动回滚；若回滚也失败，界面与日志会给出备份文件的完整路径，把它改回原文件名即可恢复。安装动作本身照常继续，界面会如实显示「旧安装器文件未能替换」及本安装器所在位置——请把它复制到原来的安装器位置，下次更新才不会再从旧版本出发。
- **旧安装器缺失时**：原位置的安装器已不存在时——原目录可写则直接按新版本重建；不可写则如实提示「未替换」，并给出新安装器所在目录，请手动把它放到固定位置。
- 更新成功交接后，本次下载的发布 zip 会被删除（解压出的新安装器正在运行，保留至 24 小时自动清理）。

> [!WARNING]
> 安装器 exe 未签名：一键更新下载的新版本安装器**首次运行时**同样可能出现「已保护你的电脑」提示——点「更多信息 → 仍要运行」（与上方「方式一」的引导一致）。

## 与鼎信诺共存

### 三个机制并存，加载通道相互独立

| 机制 | 归属 | 存在位置 |
|:---|:---|:---|
| 鼎信诺 COM 加载项 | Excel 应用 | 系统 COM 组件 |
| 鼎信诺底稿内嵌宏 | 底稿文件 | 文件内部 VBA 工程 |
| AttachLink.xlam | Excel 应用 | 外置加载项文件，不进底稿 |

> [!NOTE]
> 保存事件层面与鼎信诺/底稿内嵌宏同处一条保存链，本加载项的保存归一化为窄范围幂等操作——只精确改写本工具插入的附件链接（完整父目录比对），不依赖与鼎信诺保存宏的先后顺序。

- 鼎信诺归档剥离的是**底稿文件内部**的宏与数据库连接，xlam 在外部，剥离不到，归档件无任何残留。
- 插入的是**普通超链接**（工作表内容），不是公式也不是宏——即使归档时公式被值化，链接依然有效（这正是选普通超链接而非 `=HYPERLINK()` 公式的原因）。

### 五分钟验证流程（建议首次使用前跑一遍——覆盖「归档件自包含」全链）

1. 新建测试文件夹，放入一张测试底稿并保存
2. 用本加载项插入 1–2 个附件链接，确认：附件文件夹自动生成、文件已复制、链接可点击
3. 按鼎信诺正常流程归档（「保留公式链接」勾选与不勾选各试一次）——归档目录中的底稿链接此时仍指回账套（正常现象）
4. 在归档目录打开任一底稿，运行右键**「归档迁移（批量）」**：附件夹整体移动过来、全部底稿链接改写为相对地址
5. 运行**「附件清单 / 体检」**：应全部「正常/一致」绿字，并在附件夹内生成 `_attachlink_baseline.csv` 基线
6. **把整个归档文件夹（含底稿与附件夹）移动到新目录**，再点链接——应全部可打开（证明归档件自包含、与位置无关）
7. 故意改动一个附件内容再体检 → 出现红字「■ 内容变更」即篡改检测生效；再用右键「**附件管理 ▸ 附件版本更新**」走一遍受控更替 → 体检变「一致 v2」绿字且清单「更替记录」列留痕——版本更替与篡改的区分即验证完成

> [!IMPORTANT]
> **注意**：归档交付时保持「底稿 + 附件文件夹」同级结构整体打包（zip 内保留目录），相对链接在解压后有效。

### 归档交付与同步核对 SOP（发送方 → 网盘 → 接收方）

#### 发送方

1. 鼎信诺归档 → 在归档目录运行「归档迁移（批量）」
2. **运行一次「附件清单 / 体检」**——这一步生成内容基线 `_attachlink_baseline.csv` 并确认无断链（跳过此步，接收方首检会把收到的现状登记为基线，无法发现传输前/传输中的替换）
3. 把**整个归档目录**（全部底稿 + `附件\` 完整文件夹，含基线文件）上传企业网盘目标文件夹——多个归档各自独立成目录，**不要**合并进同一附件夹

#### 接收方

1. 在企业网盘**本地同步目录**中操作（网页预览/只下载底稿不行——附件夹必须同步到位）
2. 打开底稿点附件链接核对
3. 运行「附件清单 / 体检」：基线比对，全部「一致」即归档件完整可信
4. 出现红字「■ 内容变更」→ **反馈发送方核实**，不得自行删除基线文件「洗白」；确为有意替换的，由业务负责人确认后删除基线重建

### 自动化拉起场景与外部看门狗（根因记录）

**根因（本机逐项实测，详见 WORKLOG）**：鼎信诺通过 `CreateObject` 拉起 Excel 时，Excel 跳过 `.xlam`（OPEN 注册）、`XLSTART`、COM 加载项 `OnConnection` **三条自动初始化路径**；`AddIns` 集合中 `Installed=True` 只反映登记状态、不代表已装载。因此装载必须来自 Excel 进程**外部**。

**看门狗机制**（v1.7.0 起是预编译的 .NET 程序 `AttachLink.Watchdog.exe`，源码在 `src\WatchdogNet\`；`scripts\watchdog.ps1` 留作回退。微软文档化的 Office Native OM 附着通道，不依赖 ROT、不注入）：

```text
普通双击打开的 Excel ──► xlam 经 OPEN 注册自动装载（原有机制，正常工作）
鼎信诺拉起的 Excel   ──► 看门狗（外部常驻进程）检测 EXCEL7 文档窗口
                          └► 宿主校验：窗口所属进程必须是 EXCEL.EXE，否则跳过
                          │   （WPS 表格复用同样的窗口类名，绝不能被当成 Excel）
                          └► AccessibleObjectFromWindow 取 Application
                          └► Application.Visible 为假的实例不附着，只留意它何时变可见（v1.6.2）
                          └► 右键菜单已在位？再用 Workbooks 确认加载项确实已装载
                          │   （菜单在位 ≠ 已装载：缓存残留的「死菜单」先删掉，再按未装载处理）
                          └► Workbooks.Open(xlam) 强制装载（IsAddin 工作簿，
                          │   无可见窗口、不扰动用户；已装载时为 no-op）
                          │   ——只装载、不登记：不改动 Excel 的加载项列表
                          └► Application.Run('AttachLink.xlam'!AttachLink_Initialize) 显式初始化（幂等；宏名限定到工作簿；v1.6.4 起加载项没有 Workbook_Open，这是外部装载唯一的初始化入口）
                          └► 验证初始化成功、菜单 Tag 在位、版本可读，三项齐备才算装载完成；否则退避后重试
```

时序上恰好适配：零工作簿的自动化实例没有 EXCEL7 窗口、不会被附着；鼎信诺打开底稿（出现文档窗口）后下个周期（默认 2 秒）自动完成装载。xlam 文件不存在时（升级 / 卸载进行中）看门狗暂停附着，待文件就位后自动恢复，不向任何宿主发起调用。

v1.6.0 起看门狗**只装载、不登记**：不再把 Program Files 副本登记进 Excel 的加载项列表（v1.4.x～v1.5.x 的看门狗会在宿主退出时留下一条登记，升级 / 卸载时需要清理；安装器仍保留对这类存量登记的清理）。装载前后还会保持宿主原有的「警告显示」与「屏幕刷新」设置不变：Excel 在加载项初始化结束时会把这两项复位，若宿主是别的程序拉起的 Excel、对方关掉了警告，AttachLink 不会把它重新打开。日常手动打开的 Excel 仍由用户级安装的登记装载，所以日常也要用 AttachLink 的机器请两级都装（「一键安装」默认就是两级）。

v1.6.1 起看门狗有两处加固。① **附着失败按窗口退避**：宿主正忙（被呼叫方拒绝接收呼叫）时，同一个文档窗口按 2、4、8、16 秒退避，封顶 30 秒，期间不再打扰它，别的窗口照常处理，成功一次即恢复；此前是固定等 0.8 秒后每个周期重试。② **装载成功的判定从严**：初始化宏执行成功、右键菜单在位、版本宏可读，三项齐备才记「已装载并初始化」；缺任何一项都不算完成，日志记「装载后未能确认初始化…」并按上面的退避重试。宏名也限定到工作簿（`'AttachLink.xlam'!宏名`）。

v1.6.4 起加载项改了初始化方式：加载项自己不再带 `Workbook_Open`，也不再处理「打开工作簿」事件。双击打开 Excel 时由 `Auto_Open` 初始化；被看门狗装进别的程序拉起的 Excel 时，由上面那一步显式初始化。这样做的原因是：这两类「打开」事件的处理一执行，Excel 就会把宿主的「警告显示」「屏幕刷新」复位成开启——不只装载那一刻，之后每打开一本工作簿都会再来一次（v1.6.0 的写回只管住了装载那一刻）。改完之后，AttachLink 装进别的程序拉起的 Excel，对方关掉的提示不会再被重新打开。右键菜单的自愈只剩右键那一条（右键的瞬间补回），保存前的链接归一化不变；看门狗那一步写回保留作兜底。

v1.7.0 起看门狗本体换成了预编译的 .NET 程序 `AttachLink.Watchdog.exe`，不再运行 PowerShell 脚本。判定规则、装载流程、日志文件与措辞都与之前的 PowerShell 版逐项等价（同一批 Excel 实例上对照过），健康检查不用改判定；新增的是日志大小上限（2 MB，超过时转成一份 `AttachLinkWatchdog.prev.log`）。它依赖 .NET Framework 4.8（Windows 10 1903 以后与 Windows 11 自带），由构建脚本在本机编译，安装器打包的是编译好的产物。计划任务的直接动作仍是启动器：它旁边有 `AttachLink.Watchdog.exe` 就用它，否则退回 PowerShell 版。

v1.6.2 起，看门狗**只附着用户看得见的会话**：Excel 整体不可见的隐藏实例不再被装载，变可见之后才处理。日常使用没有变化——在鼎信诺里打开底稿时窗口是可见的，菜单照常在几秒内出现；自己双击打开的 Excel 仍由登记装载。变的是后台：各类工具、脚本在后台驱动的隐藏 Excel，以及鼎信诺归档时另起的那个隐藏 Excel，看门狗都不再往里装东西。日志里会看到「隐藏实例，暂不附着（等它可见）」，这是预期行为。

**提权注意事项**：鼎信诺以管理员运行时，Excel 为高完整性进程——

- 忽略 HKCU 的 per-user 注册（含 COM 类与受信任位置保障），必须走 **HKLM**；
- 看门狗本身需以 `RunLevel=Highest` 计划任务常驻（高完整性可附着中/高完整性双方，反之被 UIPI 拒绝）；
- **安全要求：提权进程不得从用户可写目录装载代码**，故机器级部署把 xlam 放在管理员控制的 `C:\Program Files\AttachLink\`，HKLM 受信任位置仅指向该目录（`AllowSubFolders=0`）。

## 已知限制

- 一个单元格最多一个超链接（目标格已有链接时会被新链接替换）；清单表每次整表重建（非本工具生成的同名「附件清单」表会被拒绝覆盖并提示）
- 「附件版本更新」暂不支持文件夹引用（需清除重插并重建基线，见 [FAQ.md](FAQ.md)）
- **文件夹基线语义**：校验**夹内现存文件**的内容一致性与登记完整性；不检测的缺失性变化包括**文件被删除、基线孤儿键、文件与文件夹类型互换**（现存同名文件的内容替换会检测；完整目录清单以归档交付包为准）
- 「预览」功能有意不做（系统级 QuickLook 类应用已覆盖，避免工具臃肿——2026-11-20 决策）
- 底稿必须已保存（有基准路径）才能插入
- **底稿保存在网页路径**（OneDrive / SharePoint「在桌面应用中打开」）：插入、体检、删除、文件夹引用、底稿引用、版本更新、归档迁移全部入口统一拦截，提示改为从已同步到本机的文件夹打开底稿
- **同一台机器只为一个账户服务**：多用户 / 终端服务器场景不支持（计划任务名固定，后安装的用户会覆盖先前用户的任务，任何用户卸载都会删掉整个任务）；安装器没有跨进程单实例互斥（一键更新交接需要新安装器在旧安装器仍运行时启动），请勿同时打开两个安装器
- 编制端（加载项功能）支持 Windows 桌面版 Excel 与 WPS 表格（v1.3.0 起，需 VBA 环境）；编制端不支持 Mac/网页版。归档件查看（点链接）不受限——任何表格软件均可打开归档件并点击普通超链接
- 未装 VBA 环境的 WPS 表格里没有 AttachLink 菜单（属 WPS 宿主限制，非缺陷）；此时与 Excel 共存的机器上 Excel 侧功能完整，WPS 不受看门狗影响（v1.4.3 起）
- 宏被全面禁用且无法配置受信任位置的环境不适用
- **看门狗（v1.7.0 起）依赖 .NET Framework 4.8**：Windows 10 1903 以后与 Windows 11 自带，不用另装；更老的系统上 .NET 看门狗起不来，启动器连续 3 次后会放弃，这时请以管理员运行 `build\install-elevated.ps1 -LegacyPowerShell` 退回 PowerShell 版
- **安装器 exe 未做 Authenticode 代码签名**：更新清单（latest.json）已带发布私钥签名、安装器内置公钥验签（见上方「检查更新与一键更新」的信任模型），镜像作恶或被篡改无法伪造清单；但 exe 本身的信任锚仍是 GitHub Release 渠道本身，代码签名属后续事项。新版本安装器首次运行可能出现 SmartScreen 提示（见上方引导）
- **体检取消（Esc）与保存后的状态栏提醒依赖 Excel 的状态栏 / OnTime 机制**：WPS 下若不支持则静默跳过，功能本身不受影响

### 构建

```powershell
powershell -ExecutionPolicy Bypass -File build\build.ps1
```

- 产出 `dist\AttachLink.xlam`
- 脚本临时开启「信任访问 VBA 工程对象模型」（AccessVBOM），构建结束自动还原
- `.bas` 源码按 UTF-8 读取、自动转 ANSI（GBK）后导入，中文注释与提示不乱码
- 构建后自动打开产物调用 `AttachLink_SelfTest` 做编译自检

发布打包：`build\make-manifest.ps1` 生成 `release\AttachLink-<版本>.zip`（只含 AttachLinkSetup.exe 与 README.md）与 `latest.json`（发布清单：版本、下载地址、zip 与 exe 的 SHA-256）——**`latest.json` 必须随每个版本作为 Release 附件上传**，安装器的「检查更新 / 一键更新」依赖它；清单地址固定为 `releases/latest/download/latest.json`，加速前缀列表在 `packaging\setup_update.py` 的 `MIRROR_PREFIXES`。

发布密钥与签名：发布前需先生成发布密钥对——运行 `build\new-release-key.ps1` 生成私钥（保存于 `%USERPROFILE%\.attachlink\release-key.xml`，仅当前用户可读，请另行离线备份）并在屏幕打印公钥；把打印的公钥十六进制串嵌入 `packaging\setup_update.py` 的 `RELEASE_KEY_N` 后重新构建安装器。`build\make-manifest.ps1` 每次发布会自动用私钥签名 `latest.json` 并调用安装器同款验签代码做互操作自检，不通过会中止发布。
